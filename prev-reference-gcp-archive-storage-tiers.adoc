NetApp Backup and Recovery é compatível com a camada Archive do Google Cloud Storage para backups mais antigos. Saiba mais sobre os custos de restauração e os tempos de recuperação de backups nessa camada.



[[supported-google-archival-storage-classes-for-netapp-backup-and-recovery]]
== Classes de armazenamento de arquivamento do Google com suporte para NetApp Backup and Recovery

Quando os arquivos de backup são criados inicialmente, eles são armazenados no armazenamento _Standard_. Essa camada é otimizada para armazenar dados que são acessados com pouca frequência, mas ainda permite acesso imediato.

Se o seu cluster local usa o ONTAP 9.12.1 ou posterior, você pode categorizar backups mais antigos no storage _Archive_ na UI do NetApp Backup and Recovery após um determinado número de dias (normalmente, mais de 30 dias) para otimizar ainda mais os custos. Os dados nessa camada têm um custo de recuperação mais alto, portanto, considere com que frequência você pode precisar restaurar dados desses arquivos de backup arquivados. Consulte a seção desta página sobre como restaurar dados do storage de arquivamento.

Ao configurar o NetApp Backup and Recovery com esse tipo de regra de ciclo de vida, não configure nenhuma regra de ciclo de vida ao configurar o bucket na sua conta do Google.

https://cloud.google.com/storage/docs/storage-classes["Saiba mais sobre as classes de armazenamento do Google"^].



[[restore-data-from-archival-storage]]
== Restaurar dados do armazenamento de arquivo

Armazenar arquivos de backup antigos no storage de Archive é muito menos caro do que no storage Standard. No entanto, restaurar dados de um arquivo de backup no storage de Archive leva um pouco mais de tempo e custa mais.

Quanto custa restaurar dados do Google Archive?:: Para obter preços detalhados do Google Cloud Storage por região, visite o https://cloud.google.com/storage/pricing["Página de preços do Google Cloud Storage"^] .
Quanto tempo levará para restaurar meus objetos arquivados no Google Archive?:: O tempo total de restauração é composto por duas partes:
+
--
* *Tempo de recuperação*: O tempo para recuperar o arquivo de backup do Archive e colocá-lo no armazenamento padrão.  Às vezes, isso é chamado de período de "reidratação".  Ao contrário das soluções de armazenamento "mais frias" fornecidas por outros provedores de nuvem, seus dados ficam acessíveis em milissegundos.
* *Tempo de restauração*: o tempo necessário para restaurar os dados do arquivo de backup no storage Standard. Esse tempo é o mesmo de uma restauração típica diretamente do storage Standard quando você não usa uma camada de arquivamento.


--


[NOTE]
====
Restaurar um volume ou arquivo do armazenamento de arquivo morto pode levar mais tempo. A tarefa permanece *Em andamento* no Monitor de Tarefas enquanto o Backup e Recovery tenta novamente a restauração com base na prioridade selecionada. Monitore a restauração no *Monitor de Tarefas*; ela será concluída quando a tarefa atingir um status final, como *Concluído* ou *Falha*, após todas as tentativas. Não inicie outra restauração a menos que a tarefa falhe definitivamente.
