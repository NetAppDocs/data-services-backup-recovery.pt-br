= Clone cargas de trabalho do Oracle Database com o NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Use o NetApp Backup and Recovery para criar clones graváveis de cargas de trabalho do Oracle Database a partir de sistemas ONTAP locais em storage primário ou secundário. Você também pode agendar atualizações de clones para atender às suas necessidades.

*Função necessária do NetApp Console*: superadministrador de Backup and Recovery ou administrador de clonagem de Backup and Recovery https://docs.netapp.com/us-en/console-setup-admin/reference-iam-predefined-roles.html["Saiba mais sobre as funções de acesso do NetApp Console para todos os serviços"^].



[[create-a-clone-of-an-oracle-database]]
== Crie um clone de um banco de dados Oracle

Crie um clone imediatamente a partir de um snapshot existente. Use este método para criar um clone único que não é atualizado continuamente a partir de um snapshot.

.Passos
. No menu do NetApp Console , selecione *Proteção > Backup e recuperação*.
. Em *Cargas de trabalho*, selecione o bloco *Oracle*.
. Selecione *Clone*.
. Selecione *Criar novo clone*.
. Na seção *Fonte do banco de dados*, escolha o host de origem e o banco de dados de origem nas listas.
+
.. Se o banco de dados de origem for um banco de dados contêiner (CDB), na seção *Tipo de clone*, selecione uma das seguintes opções:
+
*** *Clonagem completa do banco de dados*: Clona todo o banco de dados do contêiner, incluindo todos os PDBs.
*** *Clonagem de PDB*: Clona um PDB específico do backup do banco de dados de contêiner para um banco de dados de contêiner de destino existente.




. Na seção *Banco de dados de destino*, selecione o host de destino e o banco de dados de destino nas listas. O host de destino e o banco de dados de destino podem ser diferentes da origem.
. Selecione *Avançar*.
. Na seção *Clonar de* da página *Selecionar ponto de restauração*, selecione *Snapshots existentes*.
. Escolha um snapshot (ponto de restauração) existente na lista para usar como base para o clone e selecione *Avançar*.
+
A página *Selecionar local do Snapshot* aparece se o Snapshot estiver armazenado em mais de um local.

. Escolha o local do snapshot que deseja usar e selecione *Avançar*.
. Na página *Opções avançadas*, faça o seguinte:
+
.. Opcionalmente, se você estiver clonando um banco de dados multitenant completo, em *Configurações de clonagem completa do banco de dados*, selecione um ou mais PDBs para excluir da clonagem (o PDB $SEED é sempre excluído). Esta seção não aparece ao clonar um banco de dados de locatário único.
.. Se você já tiver salvo um arquivo de especificações, poderá ativar a opção *Personalizar parâmetros do banco de dados de destino* para carregá-lo e personalizar as configurações do banco de dados clonado. Você também pode baixar o arquivo de especificações padrão para o snapshot do banco de dados.
.. Na seção *Escopo de recuperação*, selecione uma opção para recuperar o clone usando os logs de arquivamento e insira os detalhes necessários. Selecionar *Nenhum* ignora a recuperação (o clone é criado a partir do snapshot sem aplicar as alterações dos logs de arquivamento). *Nenhum* não está disponível para clones PDB.
.. Na seção *Pré-scripts e pós-scripts*, habilite uma ou ambas as opções *Pré-script* e *Pós-script* para executar um script antes que a operação de clonagem comece ou depois que ela for concluída. Para cada opção, insira o caminho completo do script e quaisquer argumentos necessários.


. Selecione *Clone*.




[[schedule-a-clone-of-an-oracle-database]]
== Agendar a clonagem de um banco de dados Oracle

Crie um clone instantâneo e agende atualizações regulares para mantê-lo atualizado com o estado mais recente do banco de dados.


NOTE: A criação de um snapshot instantâneo e de um clone com agendamento de atualização aplica-se somente a clones completos de banco de dados. Não está disponível para um clone de PDB.

.Passos
. No menu do NetApp Console , selecione *Proteção > Backup e recuperação*.
. Em *Cargas de trabalho*, selecione o bloco *Oracle*.
. Selecione *Clone*.
. Selecione *Criar novo clone*.
. Na seção *Fonte do banco de dados*, escolha o host de origem e o banco de dados de origem nas listas.
. Na seção *Banco de dados de destino*, selecione o host de destino e o banco de dados de destino nas listas. O host de destino e o banco de dados de destino podem ser diferentes da origem.
. Selecione *Avançar*.
. Na seção *Clonar de* da página *Selecionar ponto de restauração*, selecione *Instant snapshot and clone*.
. Escolha um local para armazenar o snapshot quando ele for criado.
. Selecione *Avançar*.
. Na página *Opções avançadas*, faça o seguinte:
+
.. Para personalizar as configurações do banco de dados clonado, habilite a opção *Personalizar parâmetros do banco de dados de destino*. Se você já tiver salvo um arquivo de especificação, esta opção permite carregá-lo para personalizar as configurações do banco de dados clonado. Você também pode baixar o arquivo de especificação padrão do banco de dados, que reflete suas configurações atuais.
.. Na seção *Agendamento de atualização do clone*, escolha quando e com que frequência atualizar o clone. A atualização atualiza o Snapshot instantâneo e sobrescreve o clone existente com uma nova cópia.
.. Na seção *Pré-scripts e pós-scripts*, habilite uma ou ambas as opções *Pré-script* e *Pós-script* para executar um script antes que a operação de clonagem comece ou depois que ela for concluída. Para cada opção, insira o caminho completo do script e quaisquer argumentos necessários.


. Selecione *Clone*.




[[split-a-clone]]
== Dividir um clone

Você pode dividir um clone de suas cargas de trabalho do Oracle Database para criar uma cópia independente ou de longo prazo. A divisão de um clone cria um novo backup a partir do clone, que pode ser usado para operações de proteção e restauração.

A operação de split exibe os agregados que fazem parte da VM de storage, seus tamanhos e onde o volume clonado reside. O NetApp Backup and Recovery indica se há espaço suficiente disponível para concluir o split. Após o split, o clone se torna independente. O job de clone original permanece disponível para operações futuras.

.Passos
. No menu NetApp Backup and Recovery , selecione *Clonar*.
. Selecione um clone.
. Selecione o ícone Açõesimage:../media/icon-action.png["Opção de ações"] > *Clone dividido*.
. Revise os detalhes do clone dividido e selecione *Dividir*.
. Quando o clone dividido for criado, você poderá visualizá-lo na página *Inventário*.




[[delete-a-clone]]
== Excluir um clone

Remova clones de suas cargas de trabalho do Oracle Database para liberar espaço de storage. Se uma política proteger o clone, tanto o clone quanto o trabalho associado serão excluídos.

.Passos
. No menu NetApp Backup and Recovery , selecione *Clonar*.
. Selecione um clone.
. Selecione o ícone Açõesimage:../media/icon-action.png["Opção de ações"] > *Excluir clone*.
. Na caixa de diálogo de confirmação de exclusão do clone, revise os detalhes da exclusão.
+
.. Para excluir os recursos clonados do SnapCenter , mesmo que os clones ou seu armazenamento não estejam acessíveis, selecione *Forçar exclusão*.
.. Selecione *Excluir*.


. Quando o clone é excluído, ele é removido da página *Inventário*.
