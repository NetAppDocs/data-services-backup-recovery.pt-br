= Proteja as cargas de trabalho dos volumes do ONTAP com o NetApp Backup and Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
Use o NetApp Backup and Recovery para proteger e restaurar os dados do seu volume ONTAP e para arquivar backups para o longo prazo. Você pode implementar uma estratégia 3-2-1 com três cópias dos seus dados de origem em dois sistemas de storage diferentes e uma cópia na nuvem.

Após ativar a proteção para um sistema, o Backup and Recovery cria cópias incrementais permanentes em nível de bloco dos seus volumes. Além do volume de origem, você tem:

* Um snapshot do volume no sistema de origem
* Um volume replicado em um sistema de storage ONTAP diferente
* Um backup do volume no storage de objetos


image:diagram-321-overview-unified.png["Um diagrama que mostra como os arquivos de backup existem no sistema de origem como snapshots, como volumes replicados no sistema de storage secundário e como arquivos de backup no storage de objetos."]

A abordagem 3-2-1 oferece os seguintes benefícios:

* Várias cópias de dados protegem contra ameaças internas e externas à segurança cibernética.
* Usar diferentes tipos de mídia ajuda na recuperação caso um tipo falhe.
* Você pode restaurar rapidamente a partir da cópia local e usar as cópias externas se a cópia local estiver comprometida.


Quando necessário, você pode restaurar um _volume_ inteiro, uma _pasta_ ou um ou mais _arquivos_ a partir de qualquer uma das cópias para o mesmo sistema ou para um sistema diferente.



[[how-protection-for-ontap-volumes-works]]
== Como funciona a proteção de volumes do ONTAP

Quando você ativa o Backup and Recovery para o Cloud Volumes ONTAP ou um sistema ONTAP local, o serviço realiza uma transferência completa dos dados do seu volume. Depois disso, todas as transferências são incrementais: apenas os blocos alterados e os novos são transferidos, o que mantém o tráfego de rede no mínimo.

O backup e a recuperação usam a tecnologia SnapMirror do ONTAP para manter suas cópias sincronizadas. Ele cria snapshots no volume de origem e os transfere para os locais de replicação e backup. O backup para storage de objetos é baseado em https://docs.netapp.com/us-en/ontap/concepts/snapmirror-cloud-backups-object-store-concept.html["Tecnologia NetApp SnapMirror Cloud"^].

image:diagram-backup-recovery-general.png["Um diagrama mostrando como o NetApp Backup and Recovery se comunica com os volumes nos sistemas de origem, no sistema de armazenamento secundário e no armazenamento de objetos de destino, onde os volumes replicados e os arquivos de backup estão localizados."]

Este diagrama mostra volumes sendo replicados para um sistema Cloud Volumes ONTAP, mas você também pode replicar volumes para um sistema ONTAP local.

Cada tipo de cópia reside em um local diferente:

* Os _snapshots_ residem no volume de origem no sistema de origem.
* _Volumes replicados_ residem no sistema de storage secundário, que pode ser o Cloud Volumes ONTAP ou um sistema ONTAP local.
* _Cópias de backup_ residem em um armazenamento de objetos na sua conta na nuvem ou nas suas instalações. O Console cria um armazenamento de objetos para cada cluster. Consulte link:concept-backup-to-cloud.html#where-backups-reside-in-object-store-locations["Onde os backups residem em locais de armazenamento de objetos"] para obter detalhes sobre como o Console cria e nomeia o armazenamento de objetos.



CAUTION: Não gerencie nem altere arquivos de backup diretamente de seus sistemas de storage ou do ambiente do seu provedor de nuvem. Isso pode corromper os arquivos e resultar em uma configuração sem suporte.

Para planejar quais cópias e arquitetura usar, consulte link:prev-ontap-protect-journey.html["Planeje a proteção de volume do ONTAP"].



[[features]]
== Características

*Replicação*

* Replique dados entre sistemas de armazenamento ONTAP para dar suporte a backup e recuperação de desastres.
* Replique vários volumes FlexVol de uma vez para um sistema secundário.
* Use a criptografia em trânsito nativa do ONTAP com uma chave pré-compartilhada (PSK) entre os dois sistemas.
* Conte com a replicação com autorrecuperação em caso de falha na transferência.
* Restaurar um volume replicado para o sistema de origem ou para um sistema diferente.


Para recursos em  https://docs.netapp.com/us-en/data-services-replication/index.html["NetApp Replication"^]que não estão disponíveis ao replicar com o Backup and Recovery, consulte link:br-reference-limitations.html#replication-limitations-for-ontap-volumes["Limitações de replicação para volumes ONTAP"].

*Backup para storage de objetos*

* Faça backup de cópias independentes de seus volumes em storage de objetos de baixo custo, de sistemas locais ou na nuvem para a nuvem pública ou privada.
* Aplique uma única política de backup a todos os volumes em um cluster, atribua políticas diferentes a volumes com objetivos de ponto de recuperação exclusivos ou crie uma política que se aplique a todos os volumes futuros no cluster. Consulte link:prev-ontap-policy-manage.html["Gerenciar políticas para volumes do ONTAP"].
* Proteja seus backups contra exclusão e ransomware com DataLock e verificações de ransomware. Consulte link:prev-ontap-policy-object-options.html#datalock-and-ransomware-protection-options["Opções de proteção DataLock e Ransomware"].
* Para economizar custos, mova backups mais antigos para um armazenamento de arquivamento. Consulte link:prev-ontap-policy-object-options.html#archival-storage-options["Opções de armazenamento de arquivo"].
* Exclua a relação de backup para que você possa desativar os volumes de origem, mantendo seus backups.
* Mantenha até 4.000 backups de um único volume.
* Proteja os dados de backup com criptografia AES de 256 bits em repouso e conexões HTTPS TLS 1.2 em trânsito, ou use suas próprias chaves gerenciadas pelo cliente em vez das chaves padrão do provedor de nuvem.


*Restaurar*

* Restaurar dados de um ponto específico no tempo a partir de snapshots locais, volumes replicados ou backups em storage de objetos.
* Restaurar um volume, uma pasta ou arquivos individuais para o sistema de origem ou para um sistema diferente, incluindo um sistema que usa uma assinatura ou conta diferente, ou que esteja em uma região diferente.
* Execute uma _restauração rápida_ de um volume do storage de objetos para o Cloud Volumes ONTAP ou um sistema local quando precisar fornecer acesso ao volume o mais rápido possível, como em uma situação de recuperação de desastres.
* Restaure os dados em nível de bloco diretamente para o local especificado, preservando as ACLs originais.
* Navegue ou pesquise catálogos de arquivos para selecionar pastas e arquivos individuais para restaurar.


Consulte link:prev-ontap-restore.html["Restaurar cargas de trabalho de volumes ONTAP"] para ver as opções de restauração.



[[supported-volumes]]
== Volumes suportados

O NetApp Backup and Recovery oferece suporte aos seguintes tipos de volumes:

* Volumes de leitura e gravação FlexVol
* Volumes FlexGroup (requer ONTAP 9.12.1 ou posterior)
* Volumes SnapLock Enterprise (requer ONTAP 9.11.1 ou posterior)
* SnapLock Compliance para volumes on-premises (requer ONTAP 9.14 ou posterior)
* Volumes de destino de proteção de dados (DP) do SnapMirror



NOTE: O NetApp Backup and Recovery não oferece suporte a backups de volumes FlexCache .

Para os sistemas de origem, sistemas secundários, destinos de storage de objetos, destinos de restauração e regiões compatíveis com o Backup and Recovery, consulte link:br-start-sources-destinations.html["Destinos de backup e restauração suportados no NetApp Backup and Recovery"]. Para requisitos e restrições adicionais, consulte link:br-reference-limitations.html["Limitações conhecidas com o NetApp Backup and Recovery para volumes ONTAP"].



[[cost-and-licensing]]
== Custos e licenciamento

Você não paga nada para criar snapshots ou volumes replicados, além do espaço de disco que eles usam. As cobranças de recursos do seu provedor de nuvem e as taxas de serviço da NetApp se aplicam somente ao backup para storage de objetos.

Para obter detalhes sobre custos e opções de licenciamento, consulte link:concept-backup-to-cloud.html#cost["Saiba mais sobre o NetApp Backup and Recovery"] e link:br-start-licensing.html["Configurar o licenciamento"].
